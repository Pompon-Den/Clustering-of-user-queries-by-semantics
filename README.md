# Семантическая классификация пользовательских запросов

NLP-проект по определению категорий в коротких запросах о работе: профессия, формат занятости, характеристики кандидата и условия. Один запрос может иметь несколько меток.

Аттестационная работа по программе профессиональной переподготовки «Аналитика данных PRO DATA». Официальная тема: «Кластеризация пользовательских запросов по семантике PRO DA (FarPost)». В текущей реализации решается задача **multi-label классификации**, без алгоритмов кластеризации.

## Задача

Например, запрос «охранник вахтой без опыта» содержит три категории:

- **По должности-лемме** — охранник.
- **Занятость** — вахта.
- **По дополнительному признаку** — отсутствие опыта.

Всего предсказываются пять бинарных категорий: `занятость`, `по должности-лемме`, `по дополнительному признаку`, `по условиям`, `общие фразы`. Метрики оценивают наличие категории, а не точность извлечения конкретного названия профессии или условия.

## Данные

| Файл | Содержание | Число запросов |
|---|---|---:|
| [dataset_users_query.csv](data/dataset_users_query.csv) | Исходные пользовательские запросы | 17 370 |
| [answers.csv](data/answers.csv) | Запросы с заполненными категориями | 14 245 |
| [train_annotation_audit.csv](data/train_annotation_audit.csv) | Согласованная ручная проверка части train | 80 |

Запросы в первых двух файлах уникальны. Все строки `answers.csv` сопоставляются с исходным датасетом по точному тексту `query`. Остальные 3 125 запросов сохраняются отдельно и не участвуют в обучении и расчёте F1.

Целевые метки ML берутся из `answers.csv`: непустое значение категории означает 1, пустое — 0. У 1 709 запросов заполнено несколько категорий.

## Подход

1. Сохраняются исходный текст, нормализованный текст, леммы и вариант без стоп-слов.
2. Нормализация приводит текст к нижнему регистру и заменяет пунктуацию пробелами. Natasha выполняет лемматизацию; NLTK используется для стоп-слов. Отрицания сохраняются в текущей обработке.
3. Словарный baseline v1 сопоставляет целые слова и выражения. Версия v2 добавляет согласованные варианты профессий, возраст, график, оплату и локальную обработку отрицаний.
4. ML-модели используют TF-IDF и `MultiOutputClassifier` с Random Forest или Logistic Regression.
5. Совпадающие после очистки запросы группируются при разделении данных. TF-IDF обучается только на обучающей части внутри `Pipeline`.

## Результаты на test

Фиксированное групповое разделение: 11 362 запроса в train и 2 883 в test, `random_state=42`. Все подходы в таблице оценены на одном test по категориям из `answers.csv`.

| Подход | Micro F1 | Macro F1 | Полное совпадение пяти меток |
|---|---:|---:|---:|
| Словарный baseline v1 | 0,8911 | 0,8376 | 85,9% |
| Random Forest | 0,9252 | 0,9617 | 89,7% |
| Logistic Regression | **0,9454** | 0,9597 | **92,7%** |

Logistic Regression выше по micro F1 и полному совпадению меток; Random Forest немного выше по macro F1. Baseline v2 на test не оценивался: его правила уточнялись на train и внутренней validation.

## Эксперимент «до и после»

Способ обучения исходного notebook восстановлен для контролируемого сравнения. У всех вариантов одинаковые 9 116 обучающих запросов и 2 203 запроса validation, одинаковые параметры моделей и метки оценки из `answers.csv`. Из validation исключены группы ручного аудита. Test не участвует в этом эксперименте.

| Способ обучения | Micro F1: Random Forest | Micro F1: Logistic Regression |
|---|---:|---:|
| Старая обработка и псевдометки, с утечкой TF-IDF | 0,8663 | 0,8596 |
| Старая обработка и псевдометки, без утечки | 0,8680 | 0,8613 |
| Старая обработка, метки `answers.csv`, без утечки | **0,9460** | **0,9407** |
| Текущая обработка, метки `answers.csv`, без утечки | 0,9141 | 0,9399 |

Главный прирост дала замена псевдометок на категории из `answers.csv`. Для сравнения старого способа без утечки с текущим проведён парный bootstrap по группам, 2 000 повторов: 95% интервалы разницы micro F1 находятся выше нуля у обеих моделей.

Текущая обработка текста не дала дополнительного выигрыша: для Random Forest вариант старой обработки с новой разметкой оказался лучше, для Logistic Regression убедительного различия не выявлено. Этот вариант сохранён как результат эксперимента; рабочие модели автоматически не заменялись.

Baseline v2 на той же validation повысил micro F1 с 0,8990 до 0,9157 и macro F1 с 0,8483 до 0,9055. Его 29 проверок границ слов, отрицаний и согласованных признаков проходят.

Исторические F1 около 0,98 считались по меткам самого словарного алгоритма и с другой схемой разделения. Их нельзя напрямую сравнивать с текущими результатами.

## Анализ качества и ограничения

- Проверены 80 запросов train: 50 случайных и 30 целевых. Предложения разметки подготовлены с помощью ассистента, обсуждены и подтверждены автором проекта. Аудит используется для уточнения правил.
- Найдены несоответствия категорий тексту и расхождения критериев. Исходная разметка сохраняется; результаты рассчитываются по `answers.csv`.
- Совпадение baseline v2 на 80 примерах аудита проверяет реализацию правил на примерах их разработки и не является оценкой качества на новых запросах.
- Проверено одно разделение данных. Bootstrap оценивает разброс на выбранной validation для уже обученных моделей, без повторного обучения.
- Правила ограниченно обрабатывают отрицания, синонимы и опечатки. Отсутствие словарного совпадения может скрывать пропущенную категорию.

## Запуск

Полный запуск проверен с Python 3.10.20. Для воспроизведения рекомендуется Python 3.10: Natasha использует pymorphy2, для которого в проверенном окружении закреплён setuptools 80.10.2.

Команды ниже выполняются из корня репозитория в PowerShell:

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install "setuptools==80.10.2"
.\.venv\Scripts\python.exe -m pip install "numpy==2.2.6" "scipy==1.15.3" "pandas==2.3.3" "natasha==1.6.0" "pymorphy2==0.9.1" "nltk==3.10.3" "scikit-learn==1.7.2" "nbformat==5.11.1" "nbclient==0.11.0" "ipykernel==7.3.0"
.\.venv\Scripts\python.exe -c "import nltk; nltk.download('stopwords', raise_on_error=True)"
.\.venv\Scripts\python.exe -m ipykernel install --user --name semantic-queries --display-name "Python (semantic queries)"
```

Откройте [notebook](notebooks/semantic_query_classification.ipynb) в редакторе с поддержкой Jupyter, выберите ядро `Python (semantic queries)` и выполните **Restart Kernel & Run All**. Рабочая папка ядра должна быть `notebooks`, поскольку пути к данным начинаются с `../data/`.

Для запуска без интерфейса Jupyter из корня репозитория:

```powershell
@'
from pathlib import Path
import nbformat
from nbclient import NotebookClient

notebook_path = Path('notebooks/semantic_query_classification.ipynb')
notebook = nbformat.read(notebook_path, as_version=4)
NotebookClient(
    notebook, kernel_name='semantic-queries', timeout=1200,
    resources={'metadata': {'path': str(notebook_path.parent.resolve())}},
).execute()
nbformat.write(notebook, notebook_path)
print('Notebook executed successfully')
'@ | & .\.venv\Scripts\python.exe -
```

Полный notebook содержит 40 кодовых ячеек, включая сравнительный эксперимент. Проверенный запуск читает CSV, обрабатывает тексты и обучает модели с нуля. Ресурс NLTK загружается отдельно; при последующих запусках используются локальные файлы.
